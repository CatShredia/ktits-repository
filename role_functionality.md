# Функционал по ролям — ИС производства конвейеров

Документ описывает **фактическую реализацию** в десктоп-клиенте (`ProductionSystem.Client`) и REST API (`ProductionSystem.Api`). Сущности в БД без экранов и контроллеров (заказы, изделия и т.д.) здесь не перечисляются как доступный пользователю функционал.

## Роли в системе


| Роль        | Константа в коде | Как появляется учётная запись                    |
| ----------- | ---------------- | ------------------------------------------------ |
| Заказчик    | `Заказчик`       | Только самостоятельная **регистрация** в клиенте |
| Менеджер    | `Менеджер`       | Импорт из Excel / ручное добавление в БД         |
| Конструктор | `Конструктор`    | Импорт / БД                                      |
| Мастер      | `Мастер`         | Импорт / БД                                      |
| Директор    | `Директор`       | Импорт / БД                                      |


---

## Общий функционал (все авторизованные пользователи)

После успешного входа любая роль получает:

- **Главное окно** — открыто с момента запуска приложения; до входа рабочая область заблокирована, показывается подсказка о необходимости авторизации.
- **Окно входа** — поверх главного окна; закрывается только после успешного входа или регистрации; при закрытии без входа открывается снова.
- **Вход** (`POST /api/auth/login`) — логин и пароль, JWT-токен на последующие запросы.
- **«Запомнить меня»** — сохранение учётных данных локально (`%AppData%\ProductionSystem\credentials.json`) и попытка автоматического входа при следующем запуске.
- **Выход** — сброс сессии, очистка токена, повторный показ окна входа; главное окно не закрывается.
- **Заголовок приложения** — отображение ФИО (если есть) или логина и роли пользователя.
- **Домашний экран роли** — первый пункт меню с названием экрана по роли (пока без дополнительных операций, только заголовок).

Технически: все защищённые методы API требуют заголовок `Authorization: Bearer <token>`.

## Заказчик

### Регистрация (доступна без входа)

- **Регистрация** (`POST /api/auth/register`) — создаёт пользователя **только с ролью «Заказчик»**.
- Поля: логин, пароль, ФИО (необязательно).
- Правила пароля (клиент и API):
  - длина 4–16 символов;
  - минимум одна заглавная буква и одна цифра;
  - запрещены символы: `* & { } | +`.

После регистрации выполняется автоматический вход (выдаётся JWT).

### Меню клиента


| Раздел          | Доступ |
| --------------- | ------ |
| Экран заказчика | ✓      |
| Материалы       | ✗      |
| Комплектующие   | ✗      |
| Работники       | ✗      |


### API

- Доступны только `login` и `register` (анонимно).
- Склады, материалы, комплектующие, работники, операции — **недоступны** (401/403).

### Примечание

В модели данных есть сущности заказов (`CustomerOrder`), но **отдельного UI и API для заказчика пока нет** — экран заказчика является заглушкой под будущий функционал.

## Менеджер

### Меню клиента


| Раздел          | Доступ       |
| --------------- | ------------ |
| Экран менеджера | ✓ (заглушка) |
| Материалы       | ✓            |
| Комплектующие   | ✓            |
| Работники       | ✗            |


### Материалы и комплектующие

**Просмотр:**

- список позиций с фильтром по складу («Все склады» или конкретный склад);
- сводка: число позиций в выборке, всего в БД, суммарное количество и закупочная стоимость по выборке;
- колонки: артикул, наименование, тип, единица, количество, цена, склад, поставщик (и аналогично для комплектующих + вес).

**Редактирование** (панель под таблицей, кнопки «Сохранить» / «Удалить»):

- изменение наименования, ед. изм., количества, типа, цены закупки, ГОСТ (материалы), идентификатора склада;
- **удаление** — только если количество на складе равно **0** (иначе ошибка на API).

### API


| Метод                              | Назначение                   |
| ---------------------------------- | ---------------------------- |
| `GET /api/warehouses`              | Список складов (для фильтра) |
| `GET /api/materials?warehouseId=`  | Список материалов            |
| `PUT /api/materials/{id}`          | Обновление материала         |
| `DELETE /api/materials/{id}`       | Удаление материала           |
| `GET /api/components?warehouseId=` | Список комплектующих         |
| `PUT /api/components/{id}`         | Обновление комплектующего    |
| `DELETE /api/components/{id}`      | Удаление комплектующего      |

## Конструктор

### Меню клиента


| Раздел             | Доступ              |
| ------------------ | ------------------- |
| Экран конструктора | ✓ (заглушка)        |
| Материалы          | ✓ **только чтение** |
| Комплектующие      | ✓ **только чтение** |
| Работники          | ✗                   |


### Отличие от менеджера

Те же экраны складских позиций, но **без панели редактирования** и без кнопок сохранения/удаления (`CanEdit = false` в клиенте).

### API


| Метод                                       | Доступ  |
| ------------------------------------------- | ------- |
| `GET /api/warehouses`                       | ✓       |
| `GET /api/materials`                        | ✓       |
| `GET /api/components`                       | ✓       |
| `PUT` / `DELETE` материалов и комплектующих | ✗ (403) |

## Мастер

Функционал **совпадает с конструктором**:


| Раздел        | Доступ       |
| ------------- | ------------ |
| Экран мастера | ✓ (заглушка) |
| Материалы     | ✓ чтение     |
| Комплектующие | ✓ чтение     |
| Работники     | ✗            |


Права на API для складских данных те же, что у конструктора (только `GET`).

## Директор

### Меню клиента


| Раздел          | Доступ                        |
| --------------- | ----------------------------- |
| Экран директора | ✓ (заглушка)                  |
| Материалы       | ✓ чтение и **редактирование** |
| Комплектующие   | ✓ чтение и **редактирование** |
| Работники       | ✓ полный CRUD                 |


### Материалы и комплектующие

Как у **менеджера** (просмотр + изменение + удаление при нулевом остатке).

### Работники

- список: фамилия, возраст (из даты рождения), перечень производственных операций;
- просмотр и редактирование карточки: ФИО, дата рождения, адрес, образование, квалификация, привязка к операциям (чекбоксы);
- создание и удаление работника;
- **добавление новой производственной операции** по имени (если такой ещё нет в справочнике).

### API (дополнительно к правам менеджера)


| Метод                             | Назначение          |
| --------------------------------- | ------------------- |
| `GET /api/workers`                | Список работников   |
| `GET /api/workers/{id}`           | Карточка работника  |
| `POST /api/workers`               | Создание            |
| `PUT /api/workers/{id}`           | Обновление          |
| `DELETE /api/workers/{id}`        | Удаление            |
| `GET /api/production-operations`  | Справочник операций |
| `POST /api/production-operations` | Новая операция      |

## Источники учётных записей сотрудников

Пользователи с ролями менеджер, конструктор, мастер и директор загружаются утилитой `**ProductionSystem.Import`** из Excel (лист пользователей) при настройке БД. Пароли и логины задаются в импортируемых данных, не через экран регистрации клиента.

## Ограничения и планируемое развитие

- **Заказы, изделия, спецификации, производственные планы** — есть в схеме БД (ERD), но **не реализованы** в текущем API и клиенте.
- Домашние экраны ролей — **заглушки** (отображают только название роли).
- Пароли в БД хранятся **в открытом виде** (сравнение при входе без хеширования) — особенность текущей реализации, не ролевое ограничение.
